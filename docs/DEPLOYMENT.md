# 本地运行与数据管理

## 运行环境

Python 3.10+，安装 requirements.txt 中的 cryptography。前端由 Python 服务直接提供，不需要 Node、npm 或构建过程。推荐通过虚拟环境隔离依赖，完整命令见 README。

Windows 启动脚本会切换到脚本所在目录，优先使用本项目的 .venv；未找到时使用 PATH 中的 python。脚本不会自动下载软件或修改系统执行策略。

## 配置示例

在 PowerShell 中使用自定义本地端口：

```powershell
$env:PM_PORT = '8081'
.\.venv\Scripts\python.exe app.py
```

在 macOS / Linux：

```bash
PM_PORT=8081 .venv/bin/python app.py
```

只改变端口，不要把 PM_HOST 改为公网监听地址。访问地址应与启动输出一致。PM_DB_PATH 建议使用绝对路径；相对路径按启动进程的工作目录解析。程序不自动读取 .env。

## 数据与备份

- 默认数据目录为项目内 data/，首次运行创建 SQLite 数据库。
- Git 忽略数据库、WAL、SHM、虚拟环境和常见密钥文件；这不是防泄露保证，提交前仍应检查 git diff。
- 仅演示数据也建议停止服务后备份整个 data 目录，保留可能存在的 -wal 和 -shm 文件；不要只复制仍在写入的 .db 文件。
- 恢复前停止程序，先保存当前数据副本，再恢复同一份备份。不要将备份公开上传到 GitHub。
- 主密码不可找回；当前没有主密码修改、密码恢复、自动备份或导出功能。
- 数据库内容加密，但用户名、数量、时间和审计类别等元数据未加密。

## 常见问题

**找不到 cryptography**：用运行 app.py 的同一个 Python 执行 `-m pip install -r requirements.txt`。

**端口占用**：停止自己之前运行的实例，或设置不同的 PM_PORT；不要终止不明进程。

**忘记主密码**：不能恢复原保险库。仅测试用途可注册另一个账号；不要把删除数据库当作密码恢复。

**Cookie 无法保持登录**：普通 HTTP 本机演示应保持 PM_SECURE_COOKIE=0。设为 1 不会配置 HTTPS。不要在浏览器禁用所有 Cookie。

**完整性异常**：停止修改数据，保留原数据库和备份供排查；不要绕过 AES-GCM 认证或“忽略错误”显示数据。

**前端复制失败**：剪贴板权限和浏览器安全上下文可能影响复制；仅在可信本机浏览器里测试。

## 非生产部署声明

标准库 HTTP 服务、进程内会话和当前限流不是生产基础设施。本项目不提供公网部署、一键云托管或容器公网暴露指南。HTTPS 反向代理只是可能的实验环节，不等于获得生产安全保障。详细威胁模型见 SECURITY.md。
